# Keepy (키피) — 당겨서 미루고, 끝낸 만큼 오리가 쉬러 가는 할 일 앱

> 주제 #2109 할 일 앱 – BaaS, AI 활용 · Flutter · **앱 버전 0.7.0** (2026-11-23)
> 미니프로젝트 1단계(화면) · 2단계(저장) · 3단계(서버 동기화)를 모두 담은 최종본입니다.

Keepy 는 **제스처 중심**의 할 일 앱입니다. 할 일 블럭을 손가락으로 당겨 날짜를 바꾸고, 종이 메모를 찍어 할 일로 바꾸고,
로그인하면 **여러 기기에서 같은 목록**을 봅니다. 오늘 끝낸 만큼 오리 캐릭터의 하루가 바뀌는 **POOL PARTY** 와
태그별·일별 통계로 성취감을 줍니다.

## 1. 실행 방법

**필요한 것:** Flutter **stable 3.47.9** (팀 공통) · Chrome. 서버 동기화까지 보려면 Supabase 무료 계정.
Flutter 명령은 모두 `app` 폴더에서 실행합니다.

```powershell
# 내 작업 폴더: C:\Keepy1\app   ·   팀 저장소: C:\Keepy\Keepy\seoyoon\app   (두 곳 내용 같음)
cd C:\Keepy1\app

# 1) 처음 한 번: android/ios/web 플랫폼 폴더 생성 + 패키지 설치 + OCR·권한 설정
powershell -ExecutionPolicy Bypass -File tool\setup_platforms.ps1

# 2) 검사
flutter analyze
flutter test                 # 54개 테스트

# 3) 실행 (동기화 없이 — 이 기기에만 저장)
flutter run -d chrome

# 3') 실행 (서버 동기화 켜기 — app\.env 에 Supabase 주소·공개 키를 넣은 뒤)
flutter run -d chrome --dart-define-from-file=.env
```

- 실행 중 코드를 고쳤다면 터미널에서 `R`(대문자)로 다시 시작합니다.
- `.env` 만드는 법과 두 기기 확인 방법은 [실행 매뉴얼](docs/MP3_실행_매뉴얼.md) 에 단계별로 있습니다.
- 웹(Chrome)에서는 카메라 글자 인식 대신 붙여넣기 칸이 열리고, 휴대폰 기울기 대신 클릭으로 오리를 움직입니다.

|---|---|---|

| **메인** | 가운데 | `keepy` 로고(누르면 **오늘 통계** 펼침), ☁ 동기화 배지(로그인 시), **POOL PARTY** 오리 아이콘, 오늘 날짜, '모든 할 일', **오늘 요약** 카드, 전체/미완료/완료 탭, 지연 → 해야 할 일 → 완료한 일 구역, 편집(순서 바꾸기) |

## 3. 구현 기능 — 무엇을, 왜

### 3-1. 할 일 관리 (1·2단계 핵심)

| 기능 | 동작 | 용도 / 목적 |
|---|---|---|
| 추가 | 하단 입력 바에 쓰고 전송. 공백 제외 **1~100자**만 받고, 비어 있으면 입력 바가 흔들리며 안내 | 가장 자주 쓰는 동작을 화면 맨 아래 엄지 자리에 고정 |
| 태그 붙이기 | 입력 중 키보드 위 태그 칩 / 수정 시트 태그 칩. **태그는 하나만** — 다른 태그를 누르면 기존 태그가 자동 해제, 같은 태그를 다시 누르면 해제(=미지정) | 통계를 태그별로 정확히 나누기 위해 한 할 일 = 한 분류 |
| 완료 | 둥근 네모 체크박스 → 체크·취소선 후 '완료한 일' 로 이동 | 끝낸 일을 시각적으로 분리 |
| 수정 | 블럭을 누르면 수정 시트 (제목·태그·기한·삭제) | 한 곳에서 모든 속성 변경 |
| 삭제 | → 당기기 또는 수정 시트의 삭제 | 실수해도 되돌리기 알림으로 복구 |
| 지연 / 늦은 완료 | 기한이 지났거나, 기한 없이 만든 지 **N일(기본 3일)** 지나면 '지연'. 지연 중에 끝내면 '늦은 완료' 로 기록 | 미뤄 둔 일을 맨 위로 올려 놓치지 않게 |
| 정렬 · 순서 | 지연 → 해야 할 일 → 완료한 일. '편집' 을 누르면 ≡ 손잡이로 구역 안 순서를 끌어서 바꿈(저장됨) | 사용자가 정한 우선순위 유지 |
| 오늘 요약 카드 | 오늘 할 일 · 지연 · 오늘 완료 숫자. 누르면 날짜 화면의 오늘 / 미완료 탭 / 완료 탭으로 이동 | 앱을 열자마자 오늘 상황 파악 |
| 완료한 일 접기·비우기 | 구역 머리를 누르면 접기, '비우기' 는 확인 후 모두 삭제(알림의 '취소' 로 복원) | 완료 목록이 길어져도 깔끔하게 |
| 빈 상태 안내 | "등록된 태스크가 없습니다 / 아래에서 첫 태스크를 추가해 보세요" | 처음 쓰는 사람에게 다음 행동 안내 |
| 기기 저장 | 모든 변경을 즉시 기기에 저장(`shared_preferences`), 다시 켜도 그대로 | 2단계 '저장되는 앱' |

### 3-2. 제스처 (Keepy 의 특징)

| 조작 | 동작 | 용도 / 목적 |
|---|---|---|
| 할 일 **← 당기기** | 날짜만 설정. 당긴 거리에 따라 **+1일 → +2일 → +7일** 단계마다 걸리고(진동), 오른쪽에 "+2 / 11월 25일(수)" 표시. 놓으면 저장 | 날짜 선택 창 없이 한 손으로 미루기 |
| 당기는 중 **아래로 내리기** | 취소 (아무것도 안 바뀜) | 잘못 당겼을 때 안전하게 빠져나가기 |
| 할 일 **→ 당기기** | 삭제 버튼에 걸림 · 절반 넘게 세게 끌고 놓으면 바로 삭제 | 빠른 삭제 |
| 되돌리기 알림 | 완료·삭제·날짜 변경 뒤 0.6초 동안 '취소'. 다른 곳을 누르면 즉시 닫힘 | 실수 복구, 화면을 오래 가리지 않음 |
| 좌우로 밀기 | 빈 곳·입력 바 위·목록 맨 아래에서 화면 전환 | 3단 화면을 손가락으로 오가기 |
| 날짜 화면 목록 끝에서 더 끌기 | 할 일이 있는 이전·다음 날로 이동 | 빈 날을 건너뛰고 일정 훑기 |

### 3-3. 날짜 화면

| 기능 | 동작 | 용도 / 목적 |
|---|---|---|
| 캘린더 | 위쪽 몇 주(설정에서 1~4행). 할 일 있는 날은 칸을 색으로 채우고 완료가 많을수록 진한 초록, 오늘은 그라데이션 숫자 | 한 주의 일정 밀도를 한눈에 |
| 한 달 펼치기 | '2026년 11월' 을 누르면 한 달 전체(최대 화면 62%)가 펼쳐지고 아래 목록이 줄어듦 | 먼 날짜 고르기 |
| 고른 날 | 그날의 완료율(바/원형/그래프 중 설정)과 할 일. 이 화면에서 입력하면 고른 날이 기한 | 날짜별 계획 |
| '오늘' 버튼 | 다른 날을 보고 있으면 나타나 오늘로 복귀 | 길 잃지 않게 |

### 3-4. 태그

- 기본 태그: 과제 · 수업 · 팀 프로젝트 · 개인. 수정 시트의 ⚙ 에서 **추가·이름 변경·삭제·끌어서 순서 변경** (1~12자, 중복 불가, 최대 12개).
- 이름을 바꾸거나 지우면 그 태그가 붙은 할 일에도 바로 반영됩니다.
- 할 일 하나에 **태그는 하나만**. 태그가 없는 할 일은 통계에서 **'미지정'** 으로 셉니다.

### 3-5. 카메라 메모 → 할 일 (OCR)

가이드 화면 → 촬영/앨범 → **ML Kit 온디바이스 한글 인식** → 줄 단위로 나눈 후보(글머리표·빈 줄·중복 정리, 100자 자르기) →
검토 시트에서 글자 수정·체크 → '선택한 N개 추가'. 원본 사진은 인식 직후 지우고, 권한 거부 시 안내, 웹처럼 인식이 안 되는 환경은
붙여넣기 칸으로 대신합니다. **목적:** 종이 플래너·칠판 메모를 옮겨 적는 수고 줄이기.

### 3-6. '하루' 를 세는 기준 (오늘 요약 · 오늘 통계 · POOL PARTY · 막대 그래프 공통)

| 할 일 | 어느 날의 일로 세나 |
|---|---|
| 아직 안 끝낸 일 | 기한이 있으면 **기한 날**, 기한이 없으면 **만든 날** |
| 끝낸 일 (기본) | **끝낸 날** — 어제가 기한이던 일(지연)이나 기한 없는 일도 오늘 끝냈으면 오늘의 완료 |
| 끝낸 일 (미리 끝냄) | 기한보다 **먼저** 끝냈으면 **그 기한 날** — 24일까지인 일을 23일에 끝내면 24일의 완료 |

**목적:** "오늘 한 일" 이 실제 오늘의 노력과 맞게. 미리 끝낸 일은 그날이 되었을 때 성취로 보이고, 막대 그래프에서는 다음 날 막대가 미리 채워집니다.
(코드: `TaskStore.tasksOfDay` · `doneDayOf`)

### 3-7. 오늘 통계 (메인 화면)

- 메인의 **`keepy` 로고를 누르면** 로고와 날짜 사이에 펼쳐지고, 다시 누르면 접힙니다 (날짜 화면의 한 달 펼치기와 같은 방식, 로고 옆 ⌄ 가 상태 표시).
- 안경·학사모를 쓰고 엄지를 든 오리, **"오늘 가장 많이 한 일"** 안내 문구와 **[#수업]** 같은 태그 칩(태그 없는 일은 회색 '미지정' 칩).
- 태그별 막대: 그 태그의 오늘 할 일 수(옅게) 위에 끝낸 수(진하게). 사용자가 만든 태그 포함, **많은 순 최대 5개**("상위 5개만 출력").
- 다크 모드에서는 학사모를 연한 색으로 바꿔 어두운 카드와 구분됩니다.
- **목적:** 오늘 어떤 분야의 일을 많이 했는지 돌아보기.

### 3-8. POOL PARTY (미니게임)

설정에서 켜고 끕니다(**기본 켜짐**). 메인 오른쪽 위 오리 얼굴 아이콘으로 열고, **같은 자리에 뜨는 X** 로 닫습니다.
**목적:** 할 일을 끝낼수록 캐릭터의 하루가 '일어남 → 일함 → 휴식' 으로 바뀌어, 끝내고 싶은 동기를 줍니다.

**아래 4분의 3 — 오늘 완료율에 따른 오리 장면** (캐릭터는 직접 그린 노란 오리, 실제 마스코트는 쓰지 않음)

| 오늘 완료율 | 장면 | 라이트 모드 | 다크 모드 |
|---|---|---|---|
| 50% 미만 (할 일 0개 포함) | **아침 방**: 줄무늬 파자마·잠옷 모자·부스스한 깃털의 오리가 베개를 끌고 멀뚱멀뚱 서 있음. 뒤에 흐트러진 침대 | 커튼 양쪽 열림, 언덕 위로 막 뜬 해, 햇살 | 어두운 방, 커튼 한쪽만 열림, 막 뜬 해 |
| 50% 이상 | **책상**: 셔츠 깃·넥타이·안경 차림으로 의자에 앉아 노트북을 타닥타닥. 책상 위 노트북·커피(김)·책·스탠드, 벽에 POOL PARTY 사진 액자 (모두 옆에서 본 시점) | 커튼 양쪽 열림, 중천의 해(오후) | 커튼 모두 닫힘, 스탠드·노트북 불빛 |
| 100% | **수영장 파티**: 화면 가득 찬 물, 선글라스·튜브 낀 오리, 칵테일, 비치볼, 반짝이 | 같음 | 같음 |

100% 에서는 오리가 가만히 있어도 천천히 떠다니고, **휴대폰을 기울이면**(안드로이드·iOS 가속도 센서, 처음 자세 기준) 그쪽으로 미끄러지며,
**웹·PC 에서는 클릭한 곳으로** 둥실 갑니다. 비치볼은 혼자 떠다니다 벽이나 오리에 부딪히면 통 튕깁니다.

**위 4분의 1 — 일별 완료 막대 그래프**

- 막대 하나 = 하루, 그날 **끝낸 일만** 쌓습니다 (과제 4개 중 3개 끝내면 3칸, 4번째를 끝내면 과제 조각이 위로 길어짐).
- 막대 안은 **태그별 조각**: 많은 태그가 아래. 최대 5조각 — 태그가 6개 이상이면 위 4개만 이름으로, 나머지는 **'기타'**. 4·5번째가 같은 개수면 그 태그들도 '기타'.
- 막대 위에 그날 **완료율**, 아래에 날짜, 그 아래에 고른 날의 태그별 개수.
- **오늘 기준 7일 전 ~ 7일 뒤**. 처음엔 오늘이 가운데. 날짜 화면처럼 **좌우로 넘기면** 가운데 온 날 막대가 넓어지고, 막대를 눌러도 이동, 다른 날을 보면 **'오늘로'** 버튼.
- **목적:** 하루하루 얼마나, 어떤 일을 끝냈는지 흐름으로 보기.

### 3-9. 다크 모드

설정 > 화면 > 시스템 / 라이트 / 다크. 바탕·카드·글자·구분선·캘린더 농도·탭 바·대화상자가 함께 바뀌고, 하늘색→파란색 강조는 공통입니다.
모드를 바꾸면 화면 전체를 새 색으로 다시 그리되 보던 탭은 유지합니다. 다크 모드의 연한 글자·아이콘은 어두운 카드에서도 읽히도록 한 단계 밝게 맞췄습니다.

## 4. 서버 동기화 (3단계)

1·2단계에서 기기에만 저장하던 할 일을 **Supabase 서버로 올려**, 같은 계정으로 로그인한 두 기기가 **같은 목록**을 봅니다.
오프라인에서 쓴 할 일은 기기에 모아 두었다가 **연결되면 자동으로 반영**합니다. 로그인하지 않으면 2단계와 똑같이 이 기기에만 저장합니다.

### 4-1. 기능

| 기능 | 설명 |
|---|---|
| 회원가입·로그인·로그아웃 | 설정 > 계정 시트. 이메일·비밀번호(6자 이상), 한국어 오류 안내, 로그인 상태 기기 저장, 토큰 만료 전 자동 갱신 |
| 두 기기 동기화 | 추가·수정·완료·삭제·순서·태그가 모두 맞춰짐 |
| 오프라인 → 온라인 | 기기 장부(대기열)에 쌓았다가 연결되면 자동 반영, 오프라인이면 10초마다 재시도, 앱을 꺼도 대기열 유지 |
| 상태 표시 | 메인 ☁ 배지(✓ 맞춰짐 / ↻ 동기화 중 / ↑N 올릴 변경 / 오프라인 / 오류), 계정 시트에 마지막 동기화·올릴 변경 수·'지금 동기화' |
| 동기화 시점 | 앱 시작, 앱이 다시 앞으로 올 때, 변경 1.2초 뒤, 20초마다, '지금 동기화' |

### 4-2. 동기화 구조

```
 기기 A                                    Supabase                                   기기 B
┌──────────────┐  ① 변경 감지           ┌─────────────────────────┐           ┌──────────────┐
│ TaskStore    │──► 동기화 장부(대기열)  │ Auth (이메일·비밀번호)    │           │ TaskStore    │
│ (기기 저장)   │    기기에 저장          │ keepy_tasks             │           │              │
│              │  ② 당겨오기 ◄──────────│  user_id·id·data(JSON)  │──────────►│ ② 당겨오기    │
│              │  ③ 올리기   ──────────►│  deleted·updated_at     │◄──────────│ ③ 올리기      │
└──────────────┘                         │  synced_at  + RLS + 트리거│           └──────────────┘
                                         └─────────────────────────┘
```

| 단계 | 하는 일 | 코드 |
|---|---|---|
| ① 변경 감지 | 할 일이 바뀔 때마다 할 일별 JSON 을 장부와 비교 → 생김·바뀜·사라짐(삭제)을 '올릴 변경' 으로 표시 | `state/sync_controller.dart` `_markLocalChanges` |
| ② 당겨오기 | 마지막으로 받은 뒤 **새로 들어온 줄만**(`synced_at` 기준) 받아 반영 | `_pull`, `_applyRemoteRows` |
| ③ 올리기 | 대기열을 한 번에 올리고 성공한 것만 대기열에서 뺌 | `_push` |

### 4-3. 동기화 충돌 처리 방침

| 상황 | 처리 | 이유 |
|---|---|---|
| 두 기기에서 같은 할 일을 고침 | 할 일 단위 **마지막 수정 우선(Last-Write-Wins)**. 변경마다 기기 시각(`updated_at`, 밀리초)을 붙이고 큰 쪽이 이김. 앱(받을 때)과 서버(트리거, 쓸 때) 양쪽에서 같은 규칙 | 할 일은 짧은 항목이라 필드별 병합보다 단순·예측 가능 |
| 먼저 고친 기기가 나중에 올림(오프라인) | 서버 트리거가 더 오래된 쓰기를 **무시** → 다음 동기화 때 최신 내용을 받아 맞춤 | 늦게 온 옛 내용이 최신을 덮지 않음 |
| 삭제 | 줄을 지우지 않고 **삭제 표시(`deleted = true`)** 를 올림. 서버의 실제 DELETE 는 권한으로 막음 | 지운 사실이 전해져야 다시 살아나지 않음 |
| 한 기기는 지우고 다른 기기는 더 나중에 고침 | 나중에 고친 쪽이 이겨 되살아남 (같은 LWW) | 사용자의 마지막 의도 |
| 오프라인에서 작성·수정·삭제 | 기기 장부에 쌓고 연결되면 자동 업로드, 화면에 '오프라인 · 올릴 변경 N개' | 통과 기준 2 |
| 올리는 도중 또 고침 | 올린 시점의 버전과 같을 때만 대기열에서 뺌 | 변경 유실 방지 |
| 로그인할 때 이 기기에 할 일이 있었음 | 계정에 **합침**. 기준 시각은 '지금' 이 아니라 할 일의 마지막 수정 시각 | 오래 안 쓴 기기가 최신을 덮지 않게 |
| 서버에서 받은 변경 | 대기열에 넣지 않음 | 같은 내용이 계속 오가지 않게 |

**한계:** 기기 시계가 크게 틀리면 LWW 판정이 어긋날 수 있습니다(같은 할 일을 몇 초 안에 두 기기에서 고칠 때만). 같은 할 일의 기록 시각은
항상 앞으로만 가게 했습니다(`_stamp`). 실시간 구독(Realtime)은 넣지 않았습니다 — 통과 기준이 '새로고침 후 표시' 이고 20초 주기·앱 복귀·'지금 동기화' 로 충분합니다.
동기화 대상은 할 일뿐이고 태그 목록·화면 모드 같은 설정은 기기별입니다.

### 4-4. 선택한 BaaS 와 이유 — Supabase

| 기준 | **Supabase** (선택) | Firebase (Cloud Firestore) |
|---|---|---|
| 데이터 모델 | PostgreSQL 표 + SQL · 서버 트리거 | 문서(JSON) 컬렉션 |
| 충돌 규칙을 서버에서 강제 | 트리거 하나로 '더 오래된 쓰기 무시' 를 DB 가 보장 | 보안 규칙·트랜잭션으로 직접 구성 |
| 사용자별 데이터 분리 | 행 단위 보안(RLS) 정책 3줄 | 보안 규칙 작성 |
| Flutter 연결 | REST 라 `http` 패키지 하나로 충분 (플랫폼 설정 없음) | `flutterfire configure`, 플랫폼별 설정 파일 |
| 웹(Chrome) 실행 | 그대로 됨 | 웹 앱 등록·설정 추가 |

선택 이유: ① 충돌 규칙을 서버가 보장(`app/supabase/schema.sql` 트리거) ② 공식 SDK 대신 REST 로 `http` 하나만 더해 기존 패키지·플랫폼 설정과 충돌 없음
③ 웹까지 같은 코드라 브라우저 두 개로 '두 기기' 를 바로 재현 ④ SQL 한 파일로 누구나 같은 백엔드를 재현(여러 번 실행해도 안전).

### 4-5. 설정 키 관리 (하드코딩 금지)

| 파일 | 내용 | Git |
|---|---|---|
| `app/.env.example` | 필요한 키 이름만 (`SUPABASE_URL=`, `SUPABASE_ANON_KEY=`) + 설명 | **올림** |
| `app/.env` | 실제 값 | `.gitignore` 로 **제외** |

앱은 값을 코드에 적지 않고 실행할 때 `--dart-define-from-file=.env` → `String.fromEnvironment` 로 받습니다(`app/lib/core/env.dart`).
값이 없으면 오류 없이 **동기화가 꺼진 채** 실행됩니다. 공개 키는 `apikey` 헤더에만 싣고(새 형식 `sb_publishable_` 키는 `Authorization` 에 넣으면 거절됨),
Secret key·`service_role` 키는 절대 쓰지 않습니다. Supabase 준비 순서는 [실행 매뉴얼](docs/MP3_실행_매뉴얼.md) 1~4절.

```
         ├─ game/                 POOL PARTY 장면, 일별 막대
         └─ ocr/                  카메라·검토 시트
```

의존 방향: `ui → state → data / models`, `ui → services`, `SyncController → TaskStore · services/sync`. 화면은 저장·동기화 방식을 모릅니다.
상태는 `ChangeNotifier` 저장소 + `KeepyScope`(InheritedWidget) 로 전달하고, 모든 변경은 `TaskStore` 를 거칩니다.
